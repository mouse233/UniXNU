`device-verified`

### 硬件与依赖

- The device board points to the j716f DSC/FD and keeps vendor inputs outside the public repository.

### 操作步骤

- Build the diagnostic FD with the local UEFI checkout, audit its inputs, then boot only through boot\_b for hardware checks.

### 开发经验

- V14 reached the UniXNU menu and exercised the documented button and DarwinBoot protocol paths.
- V16 on boot\_b displayed the green ExitBootServices bar, the blue MMU-off XNU entry probe and the magenta pre-MMU-enable probe; the screen also showed the normal CapsuleRuntimeDxe LockCapsuleInterface callback.
- V17 on boot\_b waited through the post-MMU probe, executed PSCI reset, and returned to the UniXNU menu with the same three entry bars.
- V18 displayed the same three bars but later reset back to UniXNU despite replacing stage 3 with a WFE loop; the external reset/watchdog source is unresolved.
- V19/V20 added read-only reset diagnostics. V20 photographs showed the DarwinBoot pre-ExitBootServices message and a later menu, but no readable PMIC value.
- V21 was built and host-audited, flashed only to boot\_b and rebooted. A photograph confirms its large-text V21 menu and PMIC RESET: 0x02000001; the V21 XNU attempt remains unobserved.

### 完成条件

- The FD enters UniXNU, preserves the documented memory reservations, and exposes the framebuffer for the menu.

### 当前范围

- MMU-on persistence, ArmCpu/ArmDTPlatform initialization, UFS/root, userspace and iPadOS remain unverified; TzDxe is out of scope.

### 开发经验

- V15 host packaging and static audits passed.
- V16 host packaging produced the source-prelinked kernel, J716F ADT and boot image used for the boot\_b test.
- The source build applies a device-local patch-series compatibility fix before the pinned UniXNU resolver, so optional Sheng PMGR context is not required for J716F.

- Kernel and ADT inputs are reproducible, the payload contains declared files, and the boot image matches the platform header and size constraints.
